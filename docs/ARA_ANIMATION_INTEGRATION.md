# Ara runtime asset integration

## Purpose

Validate the generated Ara character assets against the Godot 4.7.2 runtime. This is a character-pipeline integration check, not an ordinary gameplay-code test: its GLB inputs are generated by the Wren Workshop workflow and are not committed to the game source tree.

## Asset hand-off

The **Build Wren Workshop** workflow generates and assembles the Ara models, then creates a runtime package containing:

- `ara_person_benchmark.glb` — complete animated Ara base-person export; animation carrier for the shared rig.
- `ara_person_body.glb` — integrated base body.
- `ara_person_modular.glb` — assembled modular body and selectable garment model.
- `ara_person_modular_underwear.glb` — modular underlayer variant.
- `ara_person_male_body.glb` — male base-body variant.

The package also contains `manifest.json`, which records the package/source commit, pinned Ara generator commit, file sizes and SHA-256 hashes.

The workflow uploads an Actions artifact named `ara-runtime-assets-<source-commit>` with 90-day retention. This makes each CI package traceable to the exact source commit. For a package that must outlive Actions artifact retention, manually dispatch **Build Wren Workshop** with a unique `release_tag`; the workflow attaches the same ZIP to an immutable-by-tag GitHub Release. Do not use a moving `latest` URL as a game dependency.

## Automated integration checks

After the Wren Workshop package is built, the separate `ara-game-integration` job downloads that exact artifact and imports it into Godot. It verifies:

1. The manifest is valid, declares the expected files and matches their SHA-256 hashes.
2. The animated benchmark imports as a scene and can be loaded by `AraCharacterActor`.
3. The benchmark contains a skeleton and animation clips; an imported animation changes the expected rig poses.
4. The body, modular outfit, underlayer outfit and male body import with renderable meshes and compatible skeleton layouts.
5. Bone names/order and rest transforms remain compatible, allowing a maximum 25 mm rest-origin difference while requiring matching bone bases.

This is an automated import/rig compatibility check. It does not prove final visual deformation quality, foot locking, root-motion handling, animation blending, or integration with gameplay movement/combat state machines; those still need in-engine visual review.

## Validation boundaries

- **Character pipeline validation:** Python tooling, GLB assembly and Blender generation.
- **Ara runtime integration:** generated GLBs + manifest imported and tested by Godot, only after the Wren Workshop build.
- **Ordinary Godot validation:** simulation, movement, combat, character appearance data and world regression tests. It must not expect generated Ara GLBs to be present.
- **Game packaging:** once a runtime asset release is selected for production, pin its release tag in the game build configuration and download that exact package before exporting the game.

The integration test is intentionally not part of `godot-validation.yml`. That workflow must remain fast, reproducible and independent of the character-generation environment.
