# Character assembly architecture audit

**Scope:** PR #87, `feature/unified-character-assembly`  
**Date:** 2026-11-11  
**Status:** Investigation only. No runtime or asset-generation code changed by this audit.

## Intended contract

One canonical character definition supplies appearance, inventory and equipped item IDs. A shared pipeline resolves a compatible Ara body, applies anatomy, assembles hairstyle/colour and profile-compatible garments/equipment, validates the result, and is used by the player, companions and NPCs.

## Runtime entry-point map

### Campaign startup and player

1. `scripts/world/world_root.gd::_ready()` creates `PlayerCharacterCreator`.
2. `scripts/ui/player_character_creator.gd::_refresh_appearance_preview()` selects one of two fixed preview assets:
   - `ara_runtime/ara_person_body.glb`
   - `ara_runtime/ara_person_male_body.glb`
3. The creator applies colours and a separate hairstyle to that generic body. Its build/height controls are approximated with whole-model scale; they do not generate the selected Ara macro body.
4. `_finish()` saves a player profile to `user://player_appearance.json` and emits it.
5. `scripts/world/world_root.gd::_on_character_created()` passes that profile to `HollowTankard`.
6. `scripts/world/hollow_tankard.gd::_create_characters()` spawns the player using the same two generic body assets. `apply_player_profile()` applies material colours and scale, but does not create a profile-specific Ara body or a profile-matched garment library.

### NPCs

1. `hollow_tankard.gd::_create_characters()` reads `data/characters/hollowmere_npcs.json`.
2. It passes each canonical record to `_spawn_character()`.
3. `_spawn_character()` selects a body by checking `art/characters/ara_runtime/bodies/<profile-id>.glb`.
4. If no profile body exists, it searches `art/characters/hollowmere/<profile-id-or-game-id>.glb` and uses that legacy complete model.
5. If neither exists, it uses a generic gendered Ara body.
6. For non-legacy models, it attempts to apply NPC appearance, attach hair, load the modular garment library, apply garment styles and apply equipment visuals.

### Shared actor

`scripts/presentation/ara_character_actor.gd` owns the low-level model load, body metadata, hair attachment/tint, garment library attachment, equipment visibility and prop attachment. It currently recognises Wren's body as a special profile and accepts the one modular garment library only for `wren_talbot`.

### Asset generation

- `tools/character_definitions.py::ara_export_params()` derives Ara export parameters from canonical `appearance` and `equipped` data.
- `tools/ara/build_hollowmere_npcs.py` can export profile-derived complete NPC GLBs and a generated `profiles.json`.
- `tools/build_ara_runtime_local.py` currently creates generic female/male assets, diagnostic assets, and explicit Wren bare/dressed/no-shoes exports. It does not yet generate a profile-keyed bare body and garment set for every canonical character.
- The Wren garment extraction pipeline is therefore a pilot, not a general profile-keyed garment system.

## Confirmed runtime/data contract mismatches

### A. NPC runtime still reads the removed `params` schema

Canonical records in `data/characters/hollowmere_npcs.json` store Ara settings under `appearance` and equipment under `equipped`. The runtime still reads `npc_profile.params` in:

- `_spawn_character()` to choose NPC gender.
- `_apply_npc_clothing_loadout()` to reconstruct clothing.
- `_spawn_character()` to call `apply_npc_parameters()`.
- `_spawn_character()` to choose hair and garment styles.

The canonical records do not have that top-level `params` field. Consequently, missing values fall back to defaults: NPC gender is treated as female, hairstyle defaults to `short02`, and the canonical appearance is not applied through the NPC path.

### B. Runtime still opens the deleted loadout file

`_create_characters()` calls `_load_starting_loadouts()`, which opens `data/characters/hollowmere_loadouts.json`. The canonical schema migration removed that file and moved owned/equipped items into each character record. This leaves a stale second-source-of-truth code path. NPC inventory and equipped state must instead be constructed from the canonical `inventory` and `equipped` fields, resolving item IDs through the catalogue.

### C. Wren-specific body and garment handling remains active

- The local builder explicitly generates `ara_person_wren_body.glb` and Wren-specific garment source exports.
- `AraCharacterActor.configure()` special-cases the Wren filename to set `body_profile_id = wren_talbot`.
- `configure_modular_garments()` rejects every other body profile.
- The runtime body selector checks a profile-specific body path, but only Wren's profile body is generated by the local runtime builder today.

Wren is not yet just another data-driven character instance.

### D. Player preview and campaign spawn use generic bodies

Both paths select the generic female/male GLBs. The player creator's body-build and height values are translated into approximate whole-body scaling, while the Ara actor warns that generic GLBs have no corresponding runtime macro morphs. The player's saved body settings are therefore not baked into the correct Ara body.

### E. Legacy complete-model fallback bypasses canonical assembly

When an NPC has no profile-generated body, the runtime can load `art/characters/hollowmere/<id>.glb`. In that branch it skips NPC appearance application, hair attachment and modular garment assembly, then applies equipment visuals to the legacy actor. This deliberately preserves old visuals during migration, but it means that the character does not follow the intended canonical appearance/equipment pipeline.

### F. Hair and material decisions are split across layers

- `ara_character_actor.gd::apply_player_profile()` tints embedded and attached hair.
- `set_hairstyle()` hides embedded hair only after a compatible separate hair asset is loaded, and restores embedded hair if attachment fails.
- `apply_npc_parameters()` constructs a new partial profile, defaults its hair colour to dark brown, then applies `hairTint` separately.
- The current NPC caller supplies an empty params dictionary because of mismatch A.
- Canonical Wren appearance contains `hairTint` (and also `hairColor`), while the runtime legacy params path expects `hairTint`.

The hair operations are not yet driven directly from one canonical appearance resolver.

### G. Two appearance/equipment representations coexist

`scripts/characters/character_appearance.gd` is a separate serializable appearance resource that recursively tints meshes and can set whole mesh visibility based on clothing slots. The Ara actor instead uses profile dictionaries and independent garment meshes. Its active call sites should be checked before removal; it must not be allowed to become a second authority over Ara body/garment visibility.

## Likely causal links to reported symptoms

| Symptom | Strong candidate from code inspection |
|---|---|
| Male NPCs look female | Runtime reads missing `params.gender`, defaults to female |
| Wren's blue braid missing/wrong | Runtime reads missing `params.hair`, defaults to `short02`; canonical `appearance.hair` is ignored |
| Wren's hair colour wrong | Runtime does not pass canonical `appearance.hairTint` through the NPC appearance path |
| NPCs naked or missing inventory clothing | Runtime reads missing `params` clothing and deleted `hollowmere_loadouts.json`, rather than canonical `equipped` |
| Player body proportions not reflected | Player preview and campaign use generic bodies; Ara macro controls are baked, not runtime morphs |
| Player clothing absent | Generic player body has no matching garment library; current library explicitly rejects non-Wren body profiles |
| NPC appearance differs from canonical record | Legacy complete-model fallback bypasses profile application and modular assembly |

These are code-path explanations, not claims that every reported visual symptom has been reproduced in the current local build.

## Additional concerns to inspect in implementation milestone

1. Confirm whether the NPC actor ID (`game_id`) and canonical profile ID are kept distinct consistently when looking up profile-keyed assets.
2. Resolve all inventory IDs and equipped slot mappings from the canonical record; do not reconstruct inventory from Ara export parameters.
3. Define a single appearance-resolver output contract used by asset generation and runtime. Do not maintain a second `params` representation as an independently mutable source.
4. Separate body-profile compatibility from character identity. Garment libraries should be keyed by compatible body/rig profile (or fit class), not by Wren's character ID.
5. Validate full skeleton rest transforms and skinning compatibility for bodies, hair and garments; bone-name equality alone is insufficient.
6. Make asset cache fingerprints include every source definition and script that can affect the generated character. Ensure cache outputs cannot silently substitute for a missing profile build.
7. Make missing assets explicit errors/statuses. Do not silently switch to a legacy complete model while presenting it as canonical assembly.
8. Audit `CharacterAppearance.apply_to()` call sites to determine whether its recursive mesh visibility behaviour can hide combined body/clothing meshes.

## Recommended correction order

1. **Data adapter/resolver:** implement one runtime resolver from canonical character record to appearance specification, inventory instances, equipped slots and Ara export parameters.
2. **NPC state construction:** remove the deleted loadout-file dependency and stop reading `npc_profile.params`; resolve directly from canonical `appearance`, `inventory` and `equipped`.
3. **Player parity:** persist the player's appearance in the same canonical schema and send it through the same resolver. Replace generic-body selection with a profile-generated body.
4. **Profile-keyed asset pipeline:** generalise Wren's body/anatomy/garment build to arbitrary profile IDs or compatible body profiles; generate a corresponding asset manifest.
5. **One runtime assembler:** use the same assembly entry point for player, Wren and all NPCs. Keep legacy models isolated as explicit temporary compatibility mode, not an implicit fallback.
6. **Retire old paths:** only after acceptance tests pass, remove Wren special cases, generic preview shortcuts, obsolete loadout files/readers, and unused appearance-resource behaviour.

## Disposition

This audit identifies confirmed data/runtime mismatches that should be fixed before more anatomy sculpting or material tweaking. It does not change code or generated assets. PR #87 remains draft and unmerged; local Blender generation and Godot visual acceptance remain separate requirements.


## Milestone 1 implementation update — 2026-11-11

The first runtime resolver pass has now been committed to this feature branch.

### Implemented

- Added `scripts/presentation/character_assembly_resolver.gd` as the common adapter for canonical NPC definitions and the player's saved creator profile.
- Both player preview and campaign spawn now use the resolver for body-variant selection and body-asset path resolution.
- Both player and NPC campaign actors enter appearance application through `AraCharacterActor.apply_resolved_appearance()`.
- NPC gender, body variant, hairstyle, hair tint, garment styles, inventory and equipped slots are read from canonical `appearance`, `inventory` and `equipped` fields.
- NPC inventory instances are created from canonical item IDs and equipped by their canonical slot mapping. The deleted `hollowmere_loadouts.json` reader and old Ara-`params` clothing reconstruction have been removed from `hollow_tankard.gd`.
- The Hollowmere manifest test now validates schema version 2 and canonical data fields. A resolver test covers Wren's profile, inventory/equipment, male body selection and player-profile adaptation.
- Godot CI now runs the resolver test and no longer tries to parse the deleted loadout file.

### Still intentionally incomplete

- Player and NPC profile-specific Ara body generation is not yet generalised. Player currently resolves to the generic gendered body; only Wren has a profile-specific body asset.
- The modular garment library is still Wren-only. Other profiles can resolve their appearance and inventory, but do not yet have profile-compatible modular clothing assets.
- Legacy complete NPC GLBs remain an explicit fallback when a profile body is unavailable. Those legacy models still bypass separate hairstyle and garment assembly.
- The actor still contains Wren-specific body/garment compatibility logic.
- This change does not modify anatomy sculpting, body geometry, skin weights, garment extraction or generated GLBs.

### Validation status

The updated Godot and character-pipeline GitHub Actions workflows were triggered for this branch. Their results must be checked before local acceptance. Local Blender generation and Godot visual testing are still separate requirements.
